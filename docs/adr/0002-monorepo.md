# ADR-0002: Monorepo

- **Статус:** Accepted
- **Дата:** 2026-11-21
- **Автор(ы):** команда ServiceDesk Lite
- **Связанные ADR:** —

## Контекст

Проект включает backend (.NET 10), frontend (React SPA), SQL-миграции и
инфраструктуру (Docker, Nginx, systemd). Все части эволюционируют вместе:
например, миграции БД и репозитории backend’а меняются одним PR-ом,
эндпоинт API и его вызов во frontend’е — тоже.

## Рассмотренные варианты

1. **Monorepo** — один репозиторий, все компоненты рядом.
2. **Multi-repo** — отдельные репозитории для backend, frontend, db, infra.
3. **Гибрид** — backend + frontend + db в одном репо, infra отдельно.

## Решение

**Monorepo**.

## Последствия

- **Положительные:**
  - Атомарные коммиты через границы компонентов (фича = один PR).
  - Единая CI-матрица и один pipeline для всех проверок.
  - Проще навигация для код-ревью и портфолио (всё видно в одном репо).
- **Отрицательные / риски:**
  - CI должен быть сегментирован по путям (paths-filter), чтобы не собирать
    frontend при изменении backend. Митигируется в этапе CI.
  - Возможен «раздутый» клон со временем. Для проекта это не проблема.
- **Что потребуется сделать:**
  - Чёткие границы директорий: `backend/`, `frontend/`, `db/`, `infra/`, `docs/`.
  - CI-workflow’ы с `paths`-фильтрами.
