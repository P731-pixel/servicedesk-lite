# ADR-0001: Использование .NET 10 LTS

- **Статус:** Accepted
- **Дата:** 2026-11-21
- **Автор(ы):** команда ServiceDesk Lite
- **Связанные ADR:** —

## Контекст

Целевая вакансия предполагает миграцию приложений на **.NET Core / .NET 6**.
.NET 6 — EOL с 12 ноября 2024. Проект greenfield, ограничений на
поддерживаемую версию .NET со стороны заказчика нет. Требуется выбрать
целевую TFM так, чтобы:

1. Использовать поддерживаемую LTS-версию (риск security-инцидентов = 0).
2. Продемонстрировать актуальные практики ASP.NET Core.
3. Код был по возможности ближе к .NET 6, чтобы при необходимости даунгрейд
   не занимал недели.

## Рассмотренные варианты

1. **.NET 6** — точное соответствие вакансии, но EOL: нет обновлений
   безопасности, современные пакеты (например, свежие Npgsql, Keycloak
   libraries) требуют ≥ .NET 8.
2. **.NET 8 LTS** — поддерживается до ноября 2026, LTS. Хороший компромисс,
   но к моменту завершения проекта приближается к EOL.
3. **.NET 10 LTS** — LTS, поддержка до 14 ноября 2028. Актуальный API,
   долгий жизненный цикл.

## Решение

Используем **.NET 10 LTS**.

## Последствия

- **Положительные:** долгий срок поддержки, современные API, «правильный»
  пример для портфолио (не EOL-фреймворк).
- **Отрицательные / риски:** не совпадает с буквой вакансии (.NET 6).
  Митигировано разделом «Совместимость с .NET 6» в README.
- **Что потребуется сделать:**
  - При необходимости даунгрейда: заменить `<TargetFramework>net10.0</TargetFramework>`
    на `net6.0` и зафиксировать версии пакетов в `Directory.Packages.props`
    (совместимые с .NET 6). Оценочно — 1–2 дня.
  - В CI собирать на .NET 10 SDK (`actions/setup-dotnet`).
